# Table

Purpose: Present structured data in rows and columns.

Use for comparison, review, sorting, or large operational lists.

Avoid for layout, simple name-value pairs, or content that is clearer as cards or lists.

Key rules:
- Keep structures simple.
- Minimize cell merging.
- Use data-table patterns for large actionable sets.
- Keep interactive headers and row actions clear.
- Prefer one record per row.

Accessibility: Preserve header relationships and avoid structures that break linear reading.

Related: `resource-list`, `card`, `table-control`.
