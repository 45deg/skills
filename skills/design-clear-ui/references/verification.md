# Follow the User's Task

Use representative content and disposable data in a safe environment. Check the needs identified before implementation at supported sizes and with keyboard operation. For a narrow change, follow affected paths rather than expand scope. Proposals cannot establish runtime behavior.

## Inspect information at the moment of use

- Start from a fresh state and perform the first useful action. Identify required prerequisites, optional setup, and any explanation that obscures progress.
- Choose among similar targets before acting. Name the cue that distinguishes the intended target without remembered IDs or positions. Check that it remains available in relevant unfinished or failed states.
- Locate targets for each relevant reason work needs attention and perform the scoped action. A route for one reason does not cover another. Check position and focus during updates; preserve legitimate alternatives.
- Make a concrete judgment using its required facts. When navigating or scrolling, identify any exact value that must be remembered or repeatedly retrieved. Working navigation and sticky labels do not prove that reference values remain available.
- Read each explanation beside its controls and status. Identify the unanswered question it resolves; remove it if existing cues already answer it. Preserve necessary conditions and accessible feedback. Check empty states and inactive conditional guidance too.

## Interrupt, correct, and continue

Exercise applicable paths rather than infer behavior from controls:

- Leave partial or invalid work, cross the required return boundary, and continue. Compare actual inputs, manual changes, identities, resources, and usable outputs. Distinguish accurate disclosure, functional restoration, and understandable return cues.
- From the returned screen, identify the task, target, progress or uncertainty, unresolved work, and next action. Execute continuation without reconstructing prior decisions or consulting earlier instructions.
- Choose a recovery route using only current cues, then compare its effect with what the UI led you to expect. Verify target, constraints, and unrelated work survive. Check independence when targets move or disappear.
- Interrupt processing or communication. Resolve uncertain outcomes and exercise supported pause, cancel, retry, and recovery without repeating completed effects. Inspect actual outputs when relevant.
- Where storage is used, simulate a failed write and follow the offered recovery to completion. Confirm the affected work survives rather than checking only the warning.

Verify keyboard paths, meaningful labels, focus, contrast, non-color cues, reduced motion, zoom, and reflow as relevant. Distinguish environment limitations from product defects.

## Report what remains

Describe the task, observed behavior, evidence, and concrete searches, remembered facts, rereading, or unexplained choices. Fix within scope and recheck. Leave unexercised behavior unverified; control counts, brevity, or reviewer familiarity do not establish user comprehension or effort.
